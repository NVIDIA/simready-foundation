# Feature: `FET014_MeshVariant`

| **Property**            | **Value**         |
|-------------------------|-------------------|
| Contract                | `FET014_MeshVariant` |
| Runtime                 | `OpenUSD` |
| Proprietary Techs       | `None` |
| Versions                | `0-1-0` |

## Description

The Visual Mesh Variant feature defines the OpenUSD contract for an asset that
offers two or more alternate visual mesh geometries within the same envelope, with
the collider unchanged. Its variation category is `MeshVariant` and its impact
class is `visual-only`.

`MeshVariant` switches a part between alternate `UsdGeomMesh` content choices
(mesh to mesh), distinct from `Representation` which switches the encoding
(mesh to splat to other). Each option is a valid mesh satisfying the geometry
requirements carried by the `FET001_MinimalPlaceableVisual` dependency.

This is not a performance level-of-detail ladder: it is alternate visual *content*
at the same envelope. Performance LOD is deferred to the forthcoming native USD LOD
system. Beyond the shared visual envelope invariant (`AV.005`), `MeshVariant` holds
the collider unchanged across options -- the same collision prims and approximation,
not merely the same size -- so only the visual mesh gprims differ. Mass and physical
material are invariant (`AV.007`).

## Use Cases

- A prop shipped with alternate sculpts or detail levels of the same object at one footprint.
- Swapping decorative mesh content while placement, collider, and mass stay fixed.
- Authoring regional or stylistic mesh variants without a second asset.
