Robot-Gripper Profile USD Authoring Guide#

This document describes how to author a USD asset that conforms to the Robot-Gripper profile.

Robot-Gripper is the consolidated gripper profile. It replaces the separate Robot-Gripper-Neutral and Robot-Gripper-Isaac profiles with a single profile whose neutral OpenUSD core is mandatory and whose solver- and runtime-specific behavior is selected through runtime features. Newton is required in 4.0.0.

Required Newton contracts — 4.0.0#

Version 4.0.0 requires FET003_RigidBody.Newton.0-1-0, FET004_Multibody.Newton.0-1-0, FET022_DrivenJoints.Newton.0-1-0, CAP000_Core.Newton.0-2-0, and CAP024_BaseArticulation.Newton.0-1-0. Install both Core and Newton tiers to resolve and validate this profile. Their requirements and runtime evidence are blocking gates.

Material binding — 4.0.0#

Robot-Gripper 4.0.0 requires FET009_MaterialCoverage.0-1-0 for material binding (VM.MAT.001) and its rendered coverage, and selects FET006_Materials.0-3-0 (required), FET006_Materials.Openpbr.0-2-0 and FET006_Materials.MDL.0-3-0 (optional), which leave VM.MAT.001 out.

Required Core — 4.0.0#

Robot-Gripper 4.0.0 requires the following Core configuration:

  • It requires CAP000_Core.0-2-0. The Core file-naming, layout, path, and undefined-prim requirements (NP.002-NP.005, NP.007, NP.008, HI.010) block validation. Through 3.0.0 the profile does not select Core. From 2.1.0 the optional runtime Core capabilities bring it in, so those requirements report only as warnings.

  • It requires CAP000_Core.Newton.0-2-0 and selects version 0-2-0 of the optional CAP000_Core.PhysX and CAP000_Core.MuJoCo capabilities. Each depends on CAP000_Core.0-2-0, so 4.0.0 validates a single Core version and does not run NP.006 or SR.001.

An asset that passed 3.0.0 must also pass the Core requirements to satisfy 4.0.0. Repair them with simready-foundation-conform-fet-000-standard before the other gates. No adapter is required.

Profile definition#

The Robot-Gripper profile includes the following feature set (see robot_gripper.toml and the feature dependency graph). Each feature’s requirements and dependencies are defined in the feature specifications.

A practical end-effector selects at least FET004_Multibody, FET022_DrivenJoints, CAP024_BaseArticulation, and FET028_Gripper. Add the PhysX features for a runnable PhysX gripper, and the Isaac features for an Isaac Sim deliverable.

Version 3.0.0 makes the baseline appearance mandatory: every conforming gripper carries a UsdPreviewSurface material (FET006_Materials). Display colour (FET010_DisplayColor), OpenPBR and MDL remain optional, so an asset picks whichever final surface its runtime needs and DISP.001 to DISP.003 are validated only on an asset that selects display colour. Requirements shared between a required and an optional feature stay required. From 3.0.0, FET006_Materials makes com.nvidia.usd.VM.BIND.001, com.nvidia.usd.VM.PS.001, VM.PS.002, VM.TEX.001 and VM.TEX.003 mandatory, and VM.MAT.001 in 3.0.0. From 4.0.0, VM.MAT.001 is required through FET009_MaterialCoverage instead. VM.BIND.002 and the OpenPBR (VM.PBR.001 to VM.PBR.003, VM.TEX.004) and MDL (VM.MDL.001, com.nvidia.usd.VM.MDL.002, VM.MDL.003, VM.TEX.005) requirements stay optional.

Required USD properties and schemas#

Stage metadata and hierarchy (FET001_MinimalPlaceableVisual)#

  • Set defaultPrim on every layer, and upAxis = "Z" with metersPerUnit = 1 on every stage.

  • Keep the prim hierarchy anchored under the default prim.

Rigid bodies and colliders (FET003_RigidBody)#

  • Apply PhysicsRigidBodyAPI to any simulated rigid body prim, which must be UsdGeomXformable.

  • Apply PhysicsCollisionAPI to collision-enabled prims.

Materials (FET006_Materials, FET010_DisplayColor, FET006_Materials.Openpbr, and FET006_Materials.MDL)#

Required from version 3.0.0. The material requirements are identical to those in the Robotics-Prop guide, which describes each requirement in full. From 4.0.0 the profile also requires FET009_MaterialCoverage, which that guide describes under Material coverage.

Optional feature requirements#

Gripper site (FET028_Gripper)#

Every gripper interaction point must be an Xform prim carrying:

  • token simready:attactment:socketType = "Gripper" — discovery attribute.

  • float custom:maxOpening — maximum jaw separation in meters, strictly positive.

  • A BasisCurves child named forward_axis with at least 2 points encoding the approach direction.

  • A BasisCurves child named grip_line with at least 2 points encoding the graspable-tube axis, whose segment length equals the physical width of the grip pads.

The gripper site prim may have any name, and multiple sites on one end-effector are supported.

Multibody joints, driven joints, and articulation#

FET004_Multibody.*, FET022_DrivenJoints.*, and CAP024_BaseArticulation.* carry the same requirements as in the Robot-Body guide.

Validation metadata (recommended)#

Include profile metadata in customLayerData to simplify validation workflows:

customLayerData = {
    dictionary SimReady_Metadata = {
        dictionary validation = {
            string profile = "Robot-Gripper"
            string profile_version = "3.0.0"
        }
    }
}
